Where OpenImport is different by design¶

  • Magento writes, not OpenImport. Rows go through Magento_ImportExport, so the result is exactly what core import would produce and upgrades keep working. No raw SQL into catalog, customer or sales tables.
  • You see before you write. The dry run shows every field that would change; delete and replace runs above a threshold wait for a typed word. Nobody else ships this today.
  • Measured, not claimed. Overhead against core's own CSV import is under 6 % on 10k and 50k products, a file with 1 % changed rows costs 2 % of a full run, and memory is flat from 10k to 50k rows. See Baseline.
  • Hardened. SSRF guard with DNS re-checks per redirect, no XML entities, zip-bomb limits, formula guard, credentials never leave the database. See Security.

Where the paid tools still have more¶

Order and tracking import, price rules and URL rewrites, job chains and more triggers, B2B. Sales entities are planned for 1.5, automation for 1.6; B2B is declined (Adobe Commerce only). See the roadmap.

Free alternatives for developers¶

What it is What it lacks for merchants
firegento/fastsimpleimport (GPL-3) PHP array API around core import, 1.2M installs no admin, no files, no schedules
techdivision/import (Pacemaker, MIT) CLI import framework writing to the database directly no admin, developer setup, many dependencies
Magento's import REST API (/V1/import/csv) base64 CSV or JSON to core import no mapping, no sources, no schedules, no preview
